# Optional Azure Responses protocol

ChatCompletions remains the default. Local LMStudio and Ollama adapters are unchanged. Azure only:

```powershell
.\AIPyTeam.ps1 -UserInput 'Describe the required Python draft' -LLMProvider AzureOpenAI -AzureOpenAIProtocol Responses -DeploymentChat $env:PSAOAI_API_AZURE_OPENAI_CC_DEPLOYMENT -Stream $false -MaxTokens 256 -AzureResponsesTimeoutSec 60 -NORAG
```

Responses reads only Process `PSAOAI_API_AZURE_OPENAI_ENDPOINT` and `PSAOAI_API_AZURE_OPENAI_KEY`; supply the deployment explicitly. Endpoint must be an HTTPS resource root or `/openai/v1/`, without query, fragment or user information. Reuses AIPSTeam/PSAOAI's existing names without duplicates: Windows DPAPI values in `PSAOAI_API_AZURE_OPENAI_KEY` are decoded in memory before `api-key` is sent; failed decode or invalid key format stops before HTTP. AIPSTeam resolves Process → User → Machine and accepts a full Responses URL; this bounded AIPyTeam adapter intentionally retains Process-only reads and root/v1 endpoint validation. Dated `PSAOAI_API_AZURE_OPENAI_APIVERSION` remains Chat-only. No credentials are stored in project state.

The effective protocol and Responses timeout are saved in Project.xml. Resume honors saved selection over the CLI protocol; legacy states lacking the selector use the provided selector (default ChatCompletions). `MaxTokens` maps to `max_output_tokens`, covering reasoning plus visible output. `store=false`, `stream=false` are explicit. Sampling parameters are omitted for all deployment aliases, without guessing the underlying model. HTTP timeout is not an independent whole-workflow deadline.

Responses streaming/SSE, tools and server-side conversation chaining are **not supported**. Set `-Stream $false`; streaming is rejected before HTTP. Only completed, nonempty assistant output_text is admitted; incomplete/error/refusal/tool-only/empty output stops, without retry or switching protocol. Adapter metadata remains available as script-scoped `LastAzureResponsesMetadata` (status, incomplete_details, usage, model and bounded error fields). It is not automatically persisted as a workflow artifact.

Native source-bound contracts and controlled full original entrypoint fresh/recovery pass on Windows PowerShell 5.1 and PowerShell 7. Full-entry uses fixture dependencies and controlled transport, not real TLS/provider inference. Fresh performs ten synthetic requests; recovery loads/exports without inference. Python exports are syntax-parsed, never executed. The initial synthetic live request returned HTTP401 because the adapter forwarded the inherited Windows DPAPI ciphertext as the api-key.
